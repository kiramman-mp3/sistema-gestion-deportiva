# Decisiones técnicas y preguntas pendientes

Este documento registra decisiones tomadas durante la implementación, discrepancias entre documentos y preguntas que requieren confirmación institucional. La fuente de requisitos sigue siendo [`requirements.md`](requirements.md).

## Decisiones técnicas

| #     | Decisión                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Motivo                                                                                                                                                                                                                                                                                        |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01  | Monorepo con npm workspaces (`apps/*`, `packages/*`).                                                                                                                                                                                                                                                                                                                                                                                                                                       | Un solo repositorio, dependencias reproducibles con `package-lock.json`, sin herramientas adicionales.                                                                                                                                                                                        |
| D-02  | Backend NestJS 12 en ESM (imports con extensión `.js`), siguiendo la plantilla oficial de `nest new`.                                                                                                                                                                                                                                                                                                                                                                                       | Es la configuración soportada por el framework; evita mezclar CJS/ESM.                                                                                                                                                                                                                        |
| D-03  | Pruebas con Vitest (API y web); lint con oxlint; formato con Prettier.                                                                                                                                                                                                                                                                                                                                                                                                                      | Es el toolchain que genera la plantilla oficial de Nest 12; se reutiliza en el frontend.                                                                                                                                                                                                      |
| D-04  | TypeScript fijado en `~6.0` (no 7.x).                                                                                                                                                                                                                                                                                                                                                                                                                                                       | `typescript-eslint`/herramientas del ecosistema aún declaran soporte `<6.1`. Revisar al actualizar.                                                                                                                                                                                           |
| D-05  | Prisma fijado en la versión exacta **7.10.0** (`prisma`, `@prisma/client`, `@prisma/adapter-pg`), sin RC. `pg` 8.23.1.                                                                                                                                                                                                                                                                                                                                                                      | El tag `latest` de `prisma` apunta a un release candidate (8.0.0-rc); 7.10.0 es la última estable (`@prisma/client` latest). Exige Node `^20.19                                                                                                                                               |     | ^22.12 |     | >=24`: compatible con Node 26 local y Node 22 de CI. |
| D-06  | Variables de entorno validadas con zod al arrancar; la API falla rápido si son inválidas.                                                                                                                                                                                                                                                                                                                                                                                                   | Evita arranques con configuración incorrecta.                                                                                                                                                                                                                                                 |
| D-07  | Swagger/OpenAPI solo fuera de producción (`/api/docs`).                                                                                                                                                                                                                                                                                                                                                                                                                                     | Reduce la superficie expuesta en producción.                                                                                                                                                                                                                                                  |
| D-08  | PostgreSQL de desarrollo enlazado únicamente a `127.0.0.1`.                                                                                                                                                                                                                                                                                                                                                                                                                                 | Evita exponer la base de datos en la red local.                                                                                                                                                                                                                                               |
| D-09  | Con Prisma 7: `prisma.config.ts` define la conexión (el `schema.prisma` ya no lleva `url`), el cliente se genera con `prisma-client` en `src/generated/prisma` (ESM, no versionado) y la conexión usa el adaptador `pg`.                                                                                                                                                                                                                                                                    | Es la configuración de la serie 7; no se aplican las de Prisma 5/6.                                                                                                                                                                                                                           |
| D-10  | El esquema, las migraciones y `prisma.config.ts` viven en `apps/api/` (no en `prisma/` de la raíz que sugiere §9.3).                                                                                                                                                                                                                                                                                                                                                                        | La API es la única que accede a la base de datos; evita rutas relativas cruzadas. §9.3 admite ajustar la estructura.                                                                                                                                                                          |
| D-11  | `overrides` en el `package.json` raíz: `mysql2@3.24.5`, `deepmerge-ts@8.0.2`.                                                                                                                                                                                                                                                                                                                                                                                                               | El CLI de Prisma 7.10.0 arrastra versiones con avisos `high` de `npm audit` (solo herramienta de desarrollo; no se usa MySQL). `npm audit fix --force` proponía bajar a Prisma 6, descartado. Verificado con migraciones, generate y pruebas. **Revisar y retirar al subir Prisma.**          |
| D-12  | Estados como enumeraciones de PostgreSQL con valores en español (`activo`, `borrador`…); identificadores `uuid` v7; `timestamptz` UTC e instantes, `date` para fechas de calendario.                                                                                                                                                                                                                                                                                                        | Coherente con `requirements.md`; detalle en `database.md`.                                                                                                                                                                                                                                    |
| D-13  | Restricciones `CHECK` y triggers (inmutabilidad de auditoría, protección de roles de sistema) en el SQL de la migración inicial.                                                                                                                                                                                                                                                                                                                                                            | Prisma no los expresa; así quedan versionados con el esquema.                                                                                                                                                                                                                                 |
| D-14  | Permisos definidos en código (`src/authz/permissions.ts`) y sincronizados por `db:seed`; solo se siembra el rol de sistema `superadmin`.                                                                                                                                                                                                                                                                                                                                                    | Cada permiso corresponde a una comprobación real del backend. Los roles institucionales dependen de la matriz que apruebe la Liga.                                                                                                                                                            |
| D-15  | Pruebas de integración en `npm run test:integration` contra una base `*_test` aislada (reemplaza al antiguo `test:e2e`).                                                                                                                                                                                                                                                                                                                                                                    | Ver `database.md`. CI usa un servicio PostgreSQL efímero.                                                                                                                                                                                                                                     |
| D-16  | Autenticación con sesiones de servidor en PostgreSQL, cookie opaca `HttpOnly`/`SameSite=Strict` (`__Host-` + `Secure` en producción), sin JWT.                                                                                                                                                                                                                                                                                                                                              | Revocación inmediata y menor superficie en el navegador. Detalle en `authentication.md`.                                                                                                                                                                                                      |
| D-17  | Contraseñas con Argon2id vía `@node-rs/argon2` 2.2.2 (binarios N-API precompilados, sin compilación nativa); `cookie` 1.1.1 para leer cabeceras.                                                                                                                                                                                                                                                                                                                                            | `argon2` (node-gyp) añade toolchain de compilación en Windows/CI; Node 22 no incluye Argon2 nativo.                                                                                                                                                                                           |
| D-18  | CSRF: token sincronizado por sesión + validación de `Origin`/`Referer` + solo `application/json` + `SameSite=Strict`.                                                                                                                                                                                                                                                                                                                                                                       | Defensa en profundidad, sin depender de un único control.                                                                                                                                                                                                                                     |
| D-19  | Limitación de intentos de login en PostgreSQL (tres claves, ventana deslizante, bloqueo temporal, sin bloqueo permanente).                                                                                                                                                                                                                                                                                                                                                                  | Persiste tras reinicios, funciona con varias instancias y no permite bloquear cuentas ajenas de forma indefinida.                                                                                                                                                                             |
| D-20  | Guards globales con denegación por defecto; permisos leídos de la BD en cada petición (sin caché).                                                                                                                                                                                                                                                                                                                                                                                          | Los cambios de permisos aplican al instante; una ruta sin política no queda abierta por error.                                                                                                                                                                                                |
| D-21  | Operaciones exitosas y su auditoría en una sola transacción (fallo ⇒ rollback); auditoría de denegaciones en mejor esfuerzo con error en el log.                                                                                                                                                                                                                                                                                                                                            | No dejar operaciones críticas sin traza, ni convertir un fallo de auditoría en una vía para ocultar o permitir intentos.                                                                                                                                                                      |
| D-22  | El primer superadministrador se crea con una CLI de operador, no con un endpoint; se niega si ya hay cualquier usuario con el rol.                                                                                                                                                                                                                                                                                                                                                          | Sin vías HTTP de elevación de privilegios.                                                                                                                                                                                                                                                    |
| D-23  | Reglas de administración: nadie se modifica a sí mismo; solo se gestiona un rol cuyos permisos se poseen; siempre al menos un superadministrador activo.                                                                                                                                                                                                                                                                                                                                    | Evita autoescalada y bloqueos del sistema.                                                                                                                                                                                                                                                    |
| D-24  | Nueva variable obligatoria `SECURITY_HASH_KEY` (HMAC de IP/correo en intentos fallidos y auditoría).                                                                                                                                                                                                                                                                                                                                                                                        | Que IP y correos no sean recuperables por fuerza bruta ante una filtración de la BD.                                                                                                                                                                                                          |
| D-25  | Permisos de catálogo: se reutilizan `*:read` y `*:manage` (ya existentes) y se añade `*:delete`; no se crean `*:create`/`*:update`. El seed solo da todos al rol de sistema `superadmin`.                                                                                                                                                                                                                                                                                                   | Respeta la convención del código; eliminar es más grave que gestionar. Ningún otro rol recibe permisos sin matriz aprobada.                                                                                                                                                                   |
| D-26  | Sin cambios de esquema para los catálogos. Categorías **sin** relación con deportes; `code` inmutable; sin campos de descripción.                                                                                                                                                                                                                                                                                                                                                           | El modelo y `requirements.md` §8.2 ya lo cubren; la relación categoría‑deporte vive en el campeonato (pendiente de la Liga).                                                                                                                                                                  |
| D-27  | Unicidad de nombres sin distinguir mayúsculas comprobada en el servicio (más los índices únicos exactos).                                                                                                                                                                                                                                                                                                                                                                                   | Un índice funcional `lower(name)` no se representa en Prisma y generaría deriva; se documentan sus límites (tildes, concurrencia).                                                                                                                                                            |
| D-28  | Ciclo de vida de temporadas provisional (borrador → activa → finalizada → archivada, con reabrir/restaurar), motivo obligatorio, borrado solo en borrador, archivada de solo lectura; sin restricción de solapamiento.                                                                                                                                                                                                                                                                      | `requirements.md` no define el ciclo; es reversible y configurable en un único archivo (`seasons.rules.ts`).                                                                                                                                                                                  |
| D-29  | Borrado físico condicionado por la base de datos (FK `RESTRICT` presentes y futuras → 409); se prefiere desactivar.                                                                                                                                                                                                                                                                                                                                                                         | Los módulos futuros quedan protegidos sin tocar este código.                                                                                                                                                                                                                                  |
| D-30  | Mensajes de validación por defecto de zod en español (`z.locales.es`).                                                                                                                                                                                                                                                                                                                                                                                                                      | Los errores de campo del servidor se muestran en la interfaz.                                                                                                                                                                                                                                 |
| D-31  | Interfaz de catálogos con un único componente genérico configurable y navegación por `#hash` sin añadir librería de rutas.                                                                                                                                                                                                                                                                                                                                                                  | Evita triplicar código y dependencias; se sustituirá por un enrutador cuando haya más pantallas.                                                                                                                                                                                              |
| D-32  | Conjunto delegable de un actor = sus propios permisos efectivos, leídos en la misma transacción tras un bloqueo asesor (`liga:privilege-changes`) que serializa todos los cambios de privilegios; reglas en `PrivilegesService`.                                                                                                                                                                                                                                                            | Un modelo mínimo y explícito que no necesita marcas adicionales; evita escaladas directas, indirectas y por concurrencia. Detalle en `administration.md`.                                                                                                                                     |
| D-33  | Nadie gestiona (edita, cambia estado, restablece credenciales o revoca roles de) una cuenta cuyos permisos excedan los suyos. **Endurece** las operaciones de la fase anterior (p. ej. un administrador con solo `users:update` ya no puede desactivar a un superadministrador).                                                                                                                                                                                                            | Sin esta regla, `users:update` permitiría tomar cualquier cuenta mediante un enlace de restablecimiento o un cambio de correo.                                                                                                                                                                |
| D-34  | Un actor no modifica un rol que él mismo tiene asignado, ni los de sistema (ni siquiera un superadministrador): los roles de sistema solo los mantiene `db:seed`.                                                                                                                                                                                                                                                                                                                           | Impide autoescalada y que la interfaz altere los privilegios base.                                                                                                                                                                                                                            |
| D-35  | Cuentas nuevas en estado `pendiente` sin contraseña (`password_hash` pasa a ser nulo, con CHECK: activa ⇒ con contraseña, pendiente ⇒ sin ella) y activación mediante un enlace de un solo uso; el administrador nunca conoce la contraseña.                                                                                                                                                                                                                                                | No hay correo ni contraseñas iniciales conocidas. Dos migraciones: valores de enum y tabla `credential_tokens`.                                                                                                                                                                               |
| D-36  | Enlaces de contraseña: 256 bits, solo SHA-256 en la BD, un solo uso atómico, vigencia `CREDENTIAL_LINK_TTL_HOURS` (24 h), token en el fragmento de la URL y borrado de la dirección.                                                                                                                                                                                                                                                                                                        | El fragmento no viaja al servidor ni en `Referer`.                                                                                                                                                                                                                                            |
| D-37  | **Recuperación autoservicio no implementada** por no existir entrega segura (correo). Solo restablecimiento asistido por un administrador.                                                                                                                                                                                                                                                                                                                                                  | No se simula un flujo que no puede completarse de forma segura.                                                                                                                                                                                                                               |
| D-38  | El cambio de contraseña propio cuenta los fallos de la contraseña actual en los mismos contadores del login y revoca las demás sesiones (se conserva la actual). Se extiende a todos los flujos la regla «no contener el usuario del correo» que ya aplicaba el bootstrap; el resto de la política no cambia.                                                                                                                                                                               | Frena la adivinación con una sesión robada; consistencia de la política.                                                                                                                                                                                                                      |
| D-39  | La auditoría consultable enmascara por nombre de campo y por forma del valor (hash, token) en el servidor, y no expone el hash de IP.                                                                                                                                                                                                                                                                                                                                                       | Protege secretos que un registro antiguo pudiera contener por error.                                                                                                                                                                                                                          |
| D-40  | Un deportista solo puede estar en un equipo por deporte y temporada (sí en varios deportes). Se impone con una restricción única `(athlete_id, sport_id, season_id)` y una clave foránea compuesta que fija deporte y temporada de la alta a los de su inscripción.                                                                                                                                                                                                                         | Regla indicada por la Liga. La garantía está en la base de datos, no solo en el servicio; el servicio comprueba antes para dar un mensaje claro.                                                                                                                                              |
| D-41  | Una **baja** de plantilla no libera el cupo; el cambio de equipo se habilita en la temporada siguiente (transferencia de club solo sin altas en temporadas borrador/activa). La excepción es la **anulación** del alta, con permiso `teams:delete` y motivo.                                                                                                                                                                                                                                | Interpretación de «acabando la temporada se habilita el cambio de equipo». Provisional: la Liga debe confirmar si hay pases o excepciones durante la temporada.                                                                                                                               |
| D-42  | El nombre de un equipo vive por temporada (`team_seasons.name`); `teams.name` es solo el valor por defecto.                                                                                                                                                                                                                                                                                                                                                                                 | Un equipo puede cambiar de nombre entre temporadas sin perder el historial.                                                                                                                                                                                                                   |
| D-43  | Habilitar a un deportista exige persona activa, fecha de nacimiento, tutor si es menor de 18 y consentimiento de tratamiento de datos vigente. Cambiar identidad o club lo devuelve a `pendiente`. **Provisional**: sustituye a los documentos de inscripción hasta definirlos.                                                                                                                                                                                                             | La Liga dejó la regla de documentos al criterio del sistema; los documentos se implementan con el almacenamiento de archivos (D-47).                                                                                                                                                          |
| D-44  | Edad de categoría = edad cumplida a la fecha de inicio de la temporada, contra `age_min`/`age_max` de la categoría (editable desde el sistema). Valores iniciales opcionales con `db:seed:provisional` (Niños 6–13, Juvenil 14–17, Liga A–D 18+), que solo crea lo inexistente.                                                                                                                                                                                                             | La Liga pidió edades inventadas pero modificables. Son provisionales; la fecha de referencia también.                                                                                                                                                                                         |
| D-45  | Alcance por club: el permiso dice qué, `club_users` dice en qué clubes; `clubs:access_all` da todos. Un club fuera de alcance responde 404. Crear, cambiar estado y eliminar clubes exigen `clubs:access_all`.                                                                                                                                                                                                                                                                              | Mantiene el modelo plano de permisos y evita revelar la existencia de recursos ajenos.                                                                                                                                                                                                        |
| D-46  | Los datos personales completos (fecha de nacimiento, documento, teléfono, tutor) viven aparte (`person_private_data`) y solo los devuelve y modifica `athletes:read_full`. El perfil público es opt‑in: marca + consentimiento vigente (revalidado en cada lectura), muestra solo nombre y club, `noindex`. Los consentimientos se revocan, no se borran. La auditoría guarda ids y nombres de campo, nunca datos personales.                                                               | Protección reforzada de menores y principio de mínimo dato. «El perfil completo solo lo ven quienes controlan el sistema».                                                                                                                                                                    |
| D-47  | Fotos y documentos de inscripción implementados con almacenamiento seguro de archivos fuera de la raíz web (`StoredFile`), tipo y tamaño validados, nombres opacos y checksum SHA-256 (`feature/registration-documents`).                                                                                                                                                                                                                                                                   | Protege archivos privados y previene ataques de ruta o subida maliciosa.                                                                                                                                                                                                                      |
| D-48  | Implementación del modelo común de participantes del ADR‑001 (`Participant`, `TeamParticipant`, `IndividualParticipant`) e inscripciones (`Registration`) vinculadas a campeonatos con reglamentos versionados (`CompetitionRuleVersion`).                                                                                                                                                                                                                                                  | Unifica la competencia tanto de equipos (fútbol, básquet) como individual (taekwondo, ajedrez) bajo una misma base de datos.                                                                                                                                                                  |
| D-49  | Detección de colisiones en la programación de encuentros (±90 min en el mismo escenario y conflicto de descanso el mismo día calendario para un mismo participante). Reprogramaciones con motivo obligatorio y auditoría.                                                                                                                                                                                                                                                                   | Evita choques de escenarios físicos y sobrecarga de participantes.                                                                                                                                                                                                                            |
| D-50  | Flujo formal de aprobación de actas de juego (`borrador` → `pendiente_revision` → `aprobado`), con revisiones históricas inmutables (`ResultRevision`) ante cualquier corrección técnica posterior.                                                                                                                                                                                                                                                                                         | Garantiza integridad y trazabilidad legal de resultados deportivos. Los borradores nunca alteran las tablas ni se publican.                                                                                                                                                                   |
| D-51  | Motor multideportivo extensible: puntuación por cuartos Q1..Q4 en básquet (reglas FIBA), combates por asaltos y faltas Gam-jeom en taekwondo, y emparejamientos con sistema Buchholz en ajedrez.                                                                                                                                                                                                                                                                                            | Cumple las exigencias funcionales de cada deporte sin bifurcar la base de datos común.                                                                                                                                                                                                        |
| D-52  | Portal público de resultados y clasificaciones (`/public/*`), con exclusión estricta de borradores, cabeceras `X-Robots-Tag: noindex, nofollow`, `Cache-Control: no-store` y saneamiento de datos de contacto o cédulas de menores.                                                                                                                                                                                                                                                         | Máxima protección de datos personales y transparencia deportiva en un solo sistema.                                                                                                                                                                                                           |
| D-53  | Documentos institucionales imprimibles con membrete de la Liga Cantonal de Quero: Acta Oficial de Encuentro (con 6 firmas reglamentarias) y Nómina de Buena Fe por club. Estilos de impresión `@media print` para hoja A4.                                                                                                                                                                                                                                                                  | Reemplaza papelería informal y formaliza el archivo físico y digital de la Liga.                                                                                                                                                                                                              |
| D-54  | Estrategia de copias de seguridad automáticas (`db:backup` / `db:restore`) con verificación de suma criptográfica SHA-256 e integración con contenedores PostgreSQL.                                                                                                                                                                                                                                                                                                                        | Garantiza continuidad operativa y recuperación ante desastres probada en entornos locales y servidores.                                                                                                                                                                                       |
| D-55  | La configuración institucional es una fila única (`institution_settings`, `id = 1` con `CHECK`), creada por la migración con los valores que estaban fijos en el código y recreada por el servicio si faltara.                                                                                                                                                                                                                                                                              | Evita pantallas vacías o errores en un despliegue nuevo y no obliga a un paso manual de «alta de la institución».                                                                                                                                                                             |
| D-56  | Parámetros de publicación del portal (clubes, deportistas, noticias, resoluciones). Lo desactivado responde 404 y las resoluciones nacen **apagadas**.                                                                                                                                                                                                                                                                                                                                      | `requirements.md` §5.1 pide «parámetros de publicación». Publicar sanciones es sensible: debe ser una decisión expresa de la Liga.                                                                                                                                                            |
| D-57  | Los textos del portal (quiénes somos, contacto, política de privacidad) son texto plano y los redacta la Liga; el sistema no incluye una política «de ejemplo». En la auditoría solo se guarda la longitud de los textos largos.                                                                                                                                                                                                                                                            | Evita inventar una base jurídica (§8.6 pide validación legal) y que la auditoría crezca con textos.                                                                                                                                                                                           |
| D-58  | Logotipo en `StoredFile` (JPG/PNG/WEBP, ≤ 5 MB), público y reemplazable; el archivo anterior se borra. Presidente, secretario/a y pie de página se guardan para los documentos oficiales.                                                                                                                                                                                                                                                                                                   | Reutiliza el almacenamiento seguro existente (D-47) y alimenta los documentos y certificados.                                                                                                                                                                                                 |
| D-59  | Dos canales de notificación: avisos dentro del sistema (siempre) y correo (solo con `MAIL_TRANSPORT=smtp`). Por defecto no se encola ningún correo.                                                                                                                                                                                                                                                                                                                                         | La Liga no ha definido proveedor ni remitente (pregunta pendiente); encolar sin poder enviar acumularía mensajes viejos.                                                                                                                                                                      |
| D-60  | El correo lleva un asunto y un cuerpo **genéricos** (título de la plantilla y un enlace al sistema). El detalle solo se ve dentro del sistema, tras iniciar sesión.                                                                                                                                                                                                                                                                                                                         | §5.14: evitar datos sensibles en asuntos o mensajes reenviables. Un título nunca contiene nombres, equipos, motivos ni fechas (lo comprueba una prueba).                                                                                                                                      |
| D-61  | Cola de correo en PostgreSQL con arrendamiento (`next_attempt_at`) y `FOR UPDATE SKIP LOCKED`; reintentos con espera creciente (5, 10, 15… min), máximo 5, y despachador en proceso cada minuto. Del error solo se guarda el código.                                                                                                                                                                                                                                                        | Sin broker adicional; seguro con varias instancias; un mensaje de error SMTP podría revelar direcciones o credenciales. La prueba de concurrencia detectó que sin arrendamiento dos despachadores enviaban el mismo correo.                                                                   |
| D-62  | Las notificaciones se crean en la misma transacción que la operación que las origina; no se avisa a quien ejecuta la acción ni a cuentas que no estén activas.                                                                                                                                                                                                                                                                                                                              | Sin avisos de operaciones revertidas ni autoavisos.                                                                                                                                                                                                                                           |
| D-63  | Destinatarios provisionales: inscripción → usuarios del club; partido reprogramado o suspendido → usuarios de los clubes participantes y árbitros designados; acta enviada a revisión → quienes tienen `results:approve`.                                                                                                                                                                                                                                                                   | La matriz real de roles la define la Liga; se usan vínculos de club y permisos existentes, sin inventar roles.                                                                                                                                                                                |
| D-64  | El recordatorio de documentación es manual (`notifications:manage`), por club, e informa solo la **cantidad** de deportistas sin documentos, nunca sus nombres.                                                                                                                                                                                                                                                                                                                             | Evita avisos automáticos repetitivos y no expone datos personales (incluidos menores) en el aviso.                                                                                                                                                                                            |
| D-65  | Un oficial reutiliza `Person` y guarda solo nombre, teléfono, licencia, deportes, club de afiliación opcional y cuenta opcional. No se guarda documento de identidad ni dirección. El teléfono lo ven solo `officials:manage` y `assignments:manage`.                                                                                                                                                                                                                                       | §5.10 pide «datos profesionales estrictamente necesarios». Reutilizar `Person` permite detectar que un árbitro es también deportista.                                                                                                                                                         |
| D-66  | Diez funciones de designación fijas (árbitro central, asistentes, cuarto árbitro, juez de mesa, cronometrista, anotador, juez de taekwondo, árbitro de ajedrez, comisario), una por función y un oficial por partido. No se restringe la función por deporte.                                                                                                                                                                                                                               | La Liga no ha definido ternas por deporte; el catálogo es amplio y la decisión queda al designador. Provisional.                                                                                                                                                                              |
| D-67  | Reglas de conflicto al designar: oficial activo, habilitado en el deporte, sin indisponibilidad, sin otra designación a menos de 90 min (duración supuesta de un partido: 120 min) y **neutralidad** (ni de su club de afiliación o ficha de deportista, ni jugador de un equipo del partido). Las designaciones de un mismo oficial se serializan con un bloqueo asesor.                                                                                                                   | Evita choques de horario (§5.10), conflictos de interés y carreras entre solicitudes. Los márgenes repiten el criterio de escenarios (D-49) y deben confirmarse con la Liga.                                                                                                                  |
